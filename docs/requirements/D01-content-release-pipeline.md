# D01 正式内容发布管线与阅读端接入

日期：2026-10-31。分支：`codex/content-release-pipeline`；基于 `codex/ios-learning-flow`。本轮继续用户要求的修复与发布准备，不填造法律内容、审核人、支持邮箱或政策网址。

## 实现与原因

1. 建立版本化 JSON schema、官方来源快照摘要、精确四段引用、原文/清单摘要及审核记录校验，防止开发样例或失效审核进入正式包。
2. 发布校验固定三法、100 卡/300 题、40/45/15 权重、19 个必需主题、四档课程、引用完整性、逐字处罚引文和六个月复核期限。不能通过删除主题的 required 标记绕过。
3. 法律审核绑定版本元数据、整部条文及来源；两名不同校对员，发布负责人和律师须为不同人员。登记与证据摘要只保证记录一致，不替代真实身份/资质核验。
4. 编译器保留所有法条字节及卡片/题目多对多关联，生成确定性 App 数据与倒排索引。先写完整临时目录再替换，拒绝覆盖来源或无关目录；总产物限制 15 MiB。
5. 正式 ContentLoader 替代原永久拒绝的占位实现，后台校验摘要/引用后加载。索引摘要错误时从已验证内容重建；正式 Release 构建重新校验审核证据和发布配置。
6. Publisher.json 集中发布信息并保持空值。正式和开发目标隔离，100 卡/300 题的跨语言合成样例只进入 Swift 测试 target。
7. 阅读页面补齐真实来源、复核日期、案例/情境标识、分类徽章、逐点引用、处罚原文与全部题目；阅读行距按字体行高的 1.6 倍计算。检索支持审核词典、全角归一化、同音词候选合并、标题优先及稳定排序。
8. V4 持久化收藏版本，保留 V1/V2/V3 迁移。旧卡片修订、已移除内容和多个迁移目标显式展示；旧版本错题不静默丢弃或改写。
9. 打开旧 SQLite 库前通过 backup API 保存包含 WAL 已提交页的一致性快照。转为独立 DELETE 日志格式后才落盘；失败保留原库。清理学习记录或收藏同步删除历史保护副本及中断的临时目录，防止删除后被恢复。
10. 增加内容工具手册、fixture 漂移检查、发布和真机文档，更新统一验证脚本。架构边界未改变，本轮未重绘架构图，沿用 Spec 中的 Archify 图。

## 验证中发现并修复

- 原备份文件仍带 WAL 文件头，独立恢复时 SQLite 返回 CANTOPEN。真实持久化回归先失败，改为备份完成后切换 DELETE 日志，再验证恢复数据、清理副本和损坏原库保留。
- 同音词只取第一项导致结果缺失；回归先见 1 条而预期 2 条，改为候选并集。别名继续递归展开会返回其他关键词甚至形成循环，加入先失败的链式别名回归，改为只展开一次后进行原文查询。
- 仅计总审核人数可能把非校对员充作第二名校对员，或让同一负责人/律师加无关人员通过。两项回归先失败，改为核对所需角色的独立人员分配后通过。
- UI 测试滑动从语速 Slider 发起，Form 未滚动；调整为页面空白区域手势。
- 最大动态字体时 UIKit 子开关的辅助功能坐标偏移，测试未真正点击可见开关。检查录屏和布局，使用带标签行对应的可见开关位置后，首启与原文阅读通过；未为测试改动产品的同意逻辑。

## 证据与边界

最终结果与日志入口见 [发布准备复核](../reviews/ios-release-readiness-2026-10-31.md)。真实法律准确性、人员审核真实性、全量内容性能与真实设备体验仍需其对应证据；不能由合成测试推断通过。

遵循 ub-mode 的先复现、最小修复、回归验证和分步记录。本机及已连接工具未提供 crapper、dryer、mutator，因此未运行 CRAP/重复率/变异工具检查，不宣称满足相应数值门槛。SwiftLint 也未运行。构建产物与测试结果留在被忽略的目录中；历史 worktree 保留以追溯各需求提交，未删除仍有验证记录的工作区。
