# iOS 发布加固：审查问题修复

分支：`codex/ios-release-hardening`；基线：`782a5f7`。按 ub-mode 先保留并执行故障复现，再最小修复。使用 SwiftData、Swift Testing、SwiftUI、性能及隐私相关 skill。签名团队由用户稍后在 Xcode 选择；邮箱、公开政策 URL、正式内容及审核人按用户要求保持未配置。

## 本轮改动与原因

1. 保留 UserSchemaV1，引入 V2 和显式迁移；答题事件增加持久化提交序号。时间仅供展示/本地日历，错题状态按提交顺序折叠，消除设备时间回拨影响。旧版本没有提交序号，迁移只能按原日期和 ID 确定性排序，无法恢复过去已经丢失的真实提交顺序。
2. 数据库故障与内容故障分开，用户库打不开时保留原库、允许只读内容和每日题查看；写操作报错并可重试。没有自动删除或重建用户库。
3. 每次写入只更新对应快照；错题历史/待复习集合在启动时构建并增量维护，消除每次写入全表刷新和题数×答题历史扫描。首次打开仍读取历史，真机大库性能尚需实测。
4. 增加事务性清除学习记录和独立清除收藏，执行前用户确认，不能相互误删。
5. 添加 `PrivacyInfo.xcprivacy` 至两个 target，并提供离线隐私页、公开政策草案及实际 Bundle 清单验证脚本。政策发布 URL 和联系邮箱未配置，不虚构。
6. 搜索改为后台一次性建立归一化字符/二元组索引，每次查询交集后校验完整短语；支持法律名称/已有别名与条号组合，拒绝畸形条号。列表采用按需构建，详情和首启保留完整阅读布局。这是开发版内存索引；正式构建时索引和审核词典仍属于 D01/D06。
7. SQLite 测试不再在 SwiftData 可能持有连接时 unlink 数据库文件；文件位于隔离测试容器临时目录，宿主退出后由测试容器生命周期清理。
